# v0.1.0-alpha Release Notes

Release status: published as a prerelease on 2026-07-08. The historical scope
below was prepared during feature freeze on 2026-07-06.

HonoWarden is pre-alpha and must not be used to store real secrets.

## Post-Release Supersession

The Scope and Not Included sections below describe the historical
`v0.1.0-alpha` release target. They are not present-tense claims about current
`main`. After that target, reviewed source added the ADR 0010 organization
foundation and owner-administered organization collection CRUD, implemented the
login-with-device flow with synthetic staging evidence while keeping production
default-off, recorded HON-124's issue-local official Desktop attachment
lifecycle, and added the inactive HON-184 encrypted text Send data/application
foundation. Send routes, token issuance, and configuration remain disabled and
explicitly unsupported pending the later activation gate. At tag time, only CLI
`2026.6.0` was `live_smoke`; the other four tag-time rows were `fixture_only`.
Post-tag Browser `2026.6.1`, Desktop `2026.6.1`, Android `2026.6.1` build
`21713`, and CLI `2026.6.0` TOTP/recent-auth runs remain narrow,
version-bound historical evidence. They do not promote the current matrix; all
five current 2026.7 rows remain `fixture_only`.

Active public inquiry routing also moved to the dedicated
`HonoWarden-inquiry-inbox` service. Its operator queue, redaction-first AI
triage, human-reviewed drafts, duplicate-safe Linear creation, and
approval-gated outbound delivery have synthetic evidence, while raw MIME and
attachment retention plus autonomous actions remain disabled. See
`docs/current-state.md`, `docs/compatibility-matrix.md`, and
`docs/security/known-limitations.md` for the current claim boundary.

  assignment beyond the creator's default collection

- collection create, update, delete, or cipher assignment behavior

- account lifecycle admin UI, live mail-provider evidence, deployed official-
  client evidence, and production lifecycle execution evidence
- login-with-device runtime workflows; ADR 0008 and the forward-only
  auth-request schema are present, but routes remain explicit 501 responses
- no live official-client attachment upload/download/delete evidence
- no live official-client user export evidence
- no live official-client or production password-change evidence
- no live official-client or production KDF-change evidence; the writer remains
  disabled in every tracked deployment configuration
- no live official-client or production account-key initialization evidence; the
  route flag remains disabled in every tracked deployment configuration
- no live official-client or production user-key rotation evidence; the writer
  remains disabled in every tracked deployment configuration
- account-key replacement, client data rewrap, V2 signature keys, signed public
  keys, security state, TDE, or Key Connector integration
- password-hint persistence; non-empty hints are rejected before mutation
- independent security audit
- broad live client matrix promotion beyond the sealed CLI `2026.6.0` tag-time
  smoke
- live_regression promotion without a ready live regression packet and redacted

- inquiry mailbox UI, AI triage, approved outbound replies, raw MIME storage,

## Compatibility

Compatibility remains conservative. The sealed `v0.1.0-alpha` tag-time matrix
promotes only CLI `2026.6.0` to `live_smoke`, backed by archived local
synthetic config, password-login, sync, account-revision, and item-lifecycle
evidence. Browser extension and Desktop `2026.6.1`, Android `2026.6.0` build
`21686`, and iOS `2026.6.0` build `3325` remain `fixture_only` in that
snapshot.

Browser extension `2026.6.1`, Desktop `2026.6.1`, Android `2026.6.1` build
`21713`, and CLI `2026.6.0` TOTP/recent-auth evidence was recorded after the
tag. It remains post-tag historical evidence: it does not rewrite the sealed
snapshot or promote any current 2026.7 row. All current rows remain
`fixture_only`. `live_regression` remains unclaimed until
`pnpm live:regression:packet -- --strict` records login, sync, item lifecycle,
refresh, session revoke, and selected auth lifecycle coverage.

## Known Risks

- no independent security audit
- remote production backup and local fresh-target restore evidence is committed,
  but no remote disposable Cloudflare restore drill has been recorded yet
- audit logging remains disabled by default until the target environment has
  migration `0007` applied and operator access approved
- user export has no dedicated global quota beyond bearer auth, recent-auth,
  password-grant login defense, and platform limits
- Worker runtime Logpush to R2 is configured, but downstream SIEM/vendor
  alerting and automated log-retention deletion are not productized
- TOTP wrapping-secret rotation lacks migration tooling
- access-token signing uses a symmetric secret without key id rotation support
- Cloudflare account-level access controls are documented, but least-privilege
  token remediation and break-glass rotation are still pending
- inquiry inbox receives only metadata by default; raw body and attachment
  retention/deletion paths must be separately enabled and evidenced before
  storing real report content
